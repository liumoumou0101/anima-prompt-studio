# 通用视觉语义生图测试方案 v1

这套测试不以“画得漂亮”为主要目标，而是检查提示词工具是否能稳定表达并保留视觉关系，以及生图模型是否能执行这些关系。机器可读用例位于 `benchmarks/visual_semantics_v1.json`。

## 一、覆盖范围

基准包含 8 个常见场景族，每族 3 级，共 24 例：

1. 空间与遮挡：在墙前、穿过墙洞、从贴身裂洞中挤出。
2. 床上与躺姿：普通侧躺、指定左右手腿、加入毯子与窗户遮挡。
3. 腿部与支撑：双脚落地、四字腿、完整左右肢体关系。
4. 手部与道具：单手持杯、双手包杯、左右手倒茶与水流。
5. 移动与环境：行走、反向回头奔跑、下楼并操作栏杆和雨伞。
6. 特效与作用范围：雨、统一风向、前景透明盾牌与局部冲击特效。
7. 双人关系：左右身份、拉腕起身、背人及四条手臂归属。
8. 镜头与构图：全身安全边界、俯拍台阶、真人与镜中倒影。

每一族的第 1 级是单关系基线，第 2 级加入方向或接触，第 3 级加入遮挡、镜头、特效或多实体组合。这样可以定位复杂度从哪一级开始失效。

## 二、第一轮：24 张快速筛查

- 使用 Luna 的同一模型版本、工作流、分辨率、采样器、步数和 CFG。
- 不使用画师 LoRA、姿势 ControlNet、高清修复或随机提示词扩展。
- 每例先生成 1 张，使用固定但不同的种子；种子建议为 `761001` 至 `761024`。
- 主测试输入必须是工具由中文 `source_zh` 产生的最终提示词，不要手工润色。
- 保存工具最终英文、最终标签、负面提示词、模型参数、种子和图片。

第一轮只用于发现问题，单张失败不能直接判定模型能力。

## 三、图片判分

逐项检查 JSON 中的 `required_facts` 和 `critical_facts`，不要凭整体观感打分。

| 项目 | 分值 | 判断方式 |
|---|---:|---|
| 必需事实 | 0–4 | 命中比例：全部 4 分，约四分之三 3 分，约一半 2 分，少量 1 分，全无 0 分 |
| 关键关系 | 0–2 | 全部正确 2 分；存在但方向、左右或作用对象有误 1 分；关系不存在 0 分 |
| 解剖与实体完整性 | 0–2 | 无明显问题 2 分；轻微手脚瑕疵 1 分；多肢体、融合、断头或主体数量错误 0 分 |
| 禁止失败 | 0–1 | 未出现 `forbidden_failures` 记 1 分，否则 0 分 |
| 总分 | 0–9 | 8–9 通过；6–7 不稳定；0–5 失败 |

无论总分多少，只要关键关系为 0，或发生主体数量错误、严重额外肢体、断头，就记为失败。

## 四、第二轮：失败项稳定性复测

对第一轮低于 8 分的项目，各生成 4 个新种子。不要只重测最难的第 3 级；同一场景族中最后一个通过级别也生成 2 张，作为该模型能完成简单版本的对照。

按 5 张结果统计：

- 4–5 张通过：首张是随机波动，不需要修改工具。
- 2–3 张通过：模型或提示结构不稳定，记录为黄色能力区。
- 0–1 张通过：进入同种子 A/B 归因。

## 五、第三轮：同种子 A/B 归因

对持续失败项，使用相同的 4 个种子比较：

- A 组：中文经过本工具得到的最终提示词。
- B 组：JSON 中的 `control_en` 直接提交给 Luna，绕过翻译、标签匹配、增强和构图推荐。

模型参数和负面提示词必须完全一致。判定规则：

| 结果 | 归因 |
|---|---|
| A 的提示词在生图前就缺少或矛盾于关键事实 | 工具语义处理错误 |
| B 明显优于 A，且通过率至少高 50 个百分点 | 工具编译或附加标签干扰 |
| A、B 都稳定失败 | Luna 对该关系的模型能力不足 |
| A、B 都时好时坏 | 模型随机稳定性不足，工具可提供风险提示但不应硬改语义 |
| A、B 都稳定通过 | 第一轮是随机波动 |

不要用不同种子比较 A/B，否则无法排除随机构图差异。

## 六、何时值得强化通用方案

只有满足下列任一条件，才应修改通用语义系统：

- 同一种关系在至少两个不同场景族中失败，例如“左右手作用对象”同时在倒茶和双人拉腕中失败。
- 某个场景族从第 2 级开始持续失败，而 B 组稳定成功。
- 工具最终提示词出现新增、丢失、反转或错误作用域，如把“身后的窗户”变成前景窗户，或把局部火花扩展成全场火花。
- 无关标签持续改变构图、身体部位或视角。

后续修复应扩展关系槽，而不是增加某一句中文的特判。建议通用槽为：

`主体 → 动作 → 目标 → 左右/方向 → 接触点 → 支撑点 → 前后遮挡 → 特效作用域 → 镜头约束 → 数量约束`

例如“右手拿壶向左手杯中倒水”应被解析为两个实体、两只手的归属、上下位置、壶嘴到杯口的有向连接，而不仅是 `teapot, cup, pouring` 三个标签。

## 七、建议记录格式

每张图片至少记录：

`case_id, lane(A/B), seed, final_prompt, required_score, relation_score, anatomy_score, forbidden_score, total, hard_failure, notes, image_path`

分析时先按 `family + level` 汇总通过率，再查看具体图片。总平均分不能代替分族结果，因为大量简单场景会掩盖少数系统性关系错误。
