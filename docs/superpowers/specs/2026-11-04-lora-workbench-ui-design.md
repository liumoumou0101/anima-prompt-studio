# LoRA 工作台操作收拢与紧凑布局

用户要求在现有首版基础上直接优化：LoRA 相关操作集中到 LoRA 区，修复选中项呈狭长竖条的界面，并补齐 MOSS 历史创作的选择入口。

## 方案与范围

采用现有共享 LoRA 组件和当前工作流切换能力。直接取消历史锁定会使用户不知情地改变复现条件，另开管理页则无法解决工作台操作分散。选择在 LoRA 区提供明确的“切换模板并编辑 LoRA”，只在点击后解除当前草稿的快照引用，历史图片和任务不变。ANIMA 已有切换逻辑移入此处，MOSS 补上等价行为。用户已明确要求实施，布局细节由实现确定，不再增加确认步骤。

## 界面与行为

- LoRA 容器占满生成参数区域；修复其被通用双列 fieldset 切成半宽的问题，其他参数布局不变。
- 已选资源改为紧凑卡片。名称、开关、模型权重与排序/移除容易找到；文本编码器权重、触发词编辑和手动服务器文件放在折叠详情中。
- 从库中选择、管理库、触发词复制、准备状态和历史切换均在 LoRA 区可达。保留最多 16 项、独立开关、顺序、模型适配过滤与缓存同步。
- 历史模式保留默认只读，切换按钮在被禁用的编辑 fieldset 外。没有兼容当前模板时显示原因；生成/提交期间不能切换。
- MOSS 独立草稿与带来源的历史会话均可选择多 LoRA。切换保留当前正负原文、手动参数、64 位种子、已有资源和当前会话隔离；之后提交不再带原快照引用。重新加载仍处于所选编辑模式。
- 浅色、深色、参数侧栏和窄窗口均可读，无横向溢出；不增加依赖。
