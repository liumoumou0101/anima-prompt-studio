# 工作台撤销与历史恢复

日期：2026-09-21。状态：交互设计 v0.2；首版已接入正式工作台，旧图默认恢复提示词和当时设置。

用户对本稿方向表示认可，并补充实际场景：LLM 更新后生成的图片看起来与之前没有区别，想回退时，单看英文提示词无法判断问题和定位回退点。以下场景作为首要验收案例；实施及验证范围见[正式工作台实施计划](../plans/2026-09-21-production-studio.md)。

配套主流程：[更新提示词与生图两步完成](2026-09-21-conversation-first-workbench-design.md)。

## 用户目标

LLM 更新可能改坏提示词，ANIMA 的新结果也可能不如旧图。用户需要迅速回到满意的内容继续尝试，且不用先保存、确认候选或理解版本编号。

这份设计分别处理最近一次编辑和更早的创作状态。只增加有明确用途的入口，不引入复杂的可视化分支树，也不要求用户手动管理分支。

## 三个日常入口

| 用户想做什么 | 入口 | 结果 |
| --- | --- | --- |
| 刚刚改坏了，退一步 | 提示词编辑区工具栏的“撤销／重做” | 撤销或重做一次完整编辑操作 |
| 之前那张图更好，从那里改 | 历史图片上的“从这张继续” | 将该图对应的创作内容载入当前工作台 |
| 想找回还没出图的一次修改 | 工具栏的“创作记录” | 按修改意见、时间和图片定位旧状态，预览后可恢复 |

用户已确认：“从这张继续”的主操作恢复该图提示词及当时设置，菜单中另有“只用提示词”保留当前模型与参数。两个动作都保留，不在每次恢复时再要求选择范围。

## 1. 撤销最近操作

撤销／重做常驻提示词编辑区工具栏。按钮旁的短说明明确对象，例如“可撤销：外套改为红色”或“可撤销：切换模型”，不用用户猜测本次会退掉什么。

一次操作应与用户的动作相符：

- 一次 LLM 更新算一步，恢复更新前的正负提示词和相关创作记忆；不回退无关的模型、工作流和参数。
- 一段连续手工编辑合并为一步，不把每个字符变成一条历史。
- 一次切换模型及由它带来的工作流、参数联动算一步，可以一起撤销。
- 一次恢复历史算一步，也能撤销。
- 生图只记录产物和实际输入，不作为“撤销一次就删除图片”的编辑步骤。保存或生图成功不能清空先前可用的编辑撤销记录。

撤销 LLM 更新时，如果输入框为空，找回触发该次更新的修改意见，方便调整后重试。如果用户已输入下一条意见，则保留这条新草稿，把旧意见留在本次记录中供取用，不覆盖新输入。

输入框内 Ctrl+Z 优先保持普通文本编辑含义；全局撤销通过清楚命名的工作台按钮触发，不劫持输入法和文本框原生撤销。

## 2. 从旧图继续

用户按图片辨认满意的结果。图片缩略图附近提供“从这张继续”，点击就载入，不要求先另存会话或手动切换版本。

主操作恢复提示词与当时设置，按钮附近说明“载入提示词和当时设置”。当前模型、工作流和参数会随之显示真实恢复后的值，不隐藏变化。

“只用提示词”作为次级操作：只载入正负文本，并建立与这份文本一致的后续改写基点；保持当前模型、工作流、采样参数、资源选择与运行条件。不导入旧 LoRA、旧锁定和旧工作流绑定。旧中文记忆不能在下一次更新时把载入文本改回去。

恢复后，编辑区显示简短来源标记，例如“从‘蓝外套·月光’继续”，并显示该图小缩略图。用户仍可直接手改、更新提示词或生成。恢复本身不调用 LLM、不生图。

仅点击旧图查看大图，不改变当前编辑基点。所有后来生成的图片和修改记录继续保留；用户不需要看到或操作底层分支结构。

## 3. 创作记录

从工具栏原位打开侧栏或抽屉，提供按时间排列的记录。

每条记录优先显示用户理解的内容：

- 修改意见，例如“外套换红色，其他保持”。
- 操作类型，例如“更新提示词”“手工编辑”“切换模型”“从旧图继续”。
- 时间、简短变化，以及关联的图片缩略图；未出图就明确显示“尚未生图”。
- 当前使用的记录有清楚标记。模型和尺寸仅在确有变化或需要辨认时摘要显示。

不在主列表突出 revision、服务端版本、编译状态等内部字段。例子：

1. 蓝外套少女，站在月光下 —— 两张图片。
2. 外套换成红色 —— 提示词已更新，一张图片。
3. 背景改成街道 —— 提示词已更新，尚未生图。
4. 从蓝外套那张继续 —— 当前编辑起点。

点击记录先查看，不自动替换编辑区。卡片上有明确的“恢复到这里”；用户可直接执行，也可先展开差异，不强制逐条审阅。只有存在可恢复内容快照的记录才提供恢复；失败日志或只有旧摘要的记录不伪装成完整存档。

“找回异常草稿”保留为恢复工具，放在创作记录的次级入口，正常回退不需要进入多窗口槽位或 JSON 导出界面。

## 恢复的一致规则

1. 恢复前自动保留完整当前草稿，包括手改文字、未发送意见、生成条件和来源，不要求用户先点保存。
2. 恢复后使用所选历史的内容；上一份未发送意见随恢复前草稿保存，输入框留空，避免自动将旧意见套到新起点上。
3. 页面反馈“已恢复到……”，提供“撤销恢复”；即使短反馈消失，工具栏撤销仍可用。
4. 撤销恢复时，原提示词、条件和原未发送意见一起回来。
5. 恢复生成新的当前状态，不截断或删除之后的历史。撤销后再做新编辑可能结束快捷重做路径，但旧内容仍能从创作记录找回。
6. 备份失败时保持编辑区不变，原位说明失败。这是实际保存故障，不是每次恢复前的确认流程。

## 请求进行中与旧记录边界

- LLM 正在改写同一编辑区时，恢复必须先停止或使本次更新失效；不得让迟到结果覆盖恢复后的内容。“更新并生图”的尚未执行部分同步失效。
- 已经提交的生图任务保持原输入继续运行，回退只改变下一次编辑与生成的起点；完成图片归属于原任务，不重新覆盖当前编辑。界面用非阻断文字说明“正在生成的任务仍使用提交时内容”。
- 接受结果未知的请求继续按原请求核对，回退不删除其恢复记录，也不触发第二次提交。
- 历史图参数或单图实际种子缺失时，明确显示未知；不把批次种子冒充单图种子，不承诺完整重现。可以只恢复已知提示词，不猜测缺失值。
- 旧工作流或资源不可用时，仍允许查看和载入已知内容。实际再次生成前在运行条件处解决问题，不因环境离线阻止查看历史。
- 刷新后重要创作节点及恢复前草稿仍可找回；不承诺浏览器原生逐字符撤销跨刷新保留。

## 与当前实现的差异

当前采用模型结果会通过 adopt 清空快捷撤销栈；历史恢复又因 dirty、未发送意见或候选而禁用。新设计要保证“更新完成后能马上撤销”和“有当前草稿也能恢复历史”这两个关键行为。

当前版本列表主要以版本编号和通用保存说明呈现。新创作记录复用实际保存数据及图片来源关联，按有意义的动作组织展示，不为每次自动草稿写入增加一个用户可见节点。

## 验收场景

### 首要案例：更新之后，图片看起来没有变化

1. 用户在图片 A 的基础上输入中文修改意见，更新提示词后生成图片 B。
2. 创作记录能将这句修改意见、此次提示词更新和图片 B 关联起来，图片 A 保留且容易找到。用户无需阅读英文，即可按中文意见和缩略图辨认前后两个节点。
3. 用户可并排查看 A、B，点击 A 的“从这张继续”，恢复 A 的提示词和当时设置；编辑区明确显示从 A 继续。B 及其修改记录保留，恢复本身不生图。
4. 如需排查原因，详情显示 B 实际提交的提示词与条件，并与 A 对比。能确定的“提示词未变化”“使用了更新后的提示词”“模型／参数发生变化”由实际记录得出，不根据当前编辑区或 LLM 自述推断。
5. 更新后的文字与实际生成使用的文字是否一致，必须可核对。修改意见是用户意图，LLM 的改写说明是辅助信息，两者都不能替代提交快照作为生效证据。
6. 仅凭两张图看起来相似，不能断言修改没有应用，也不能认定 ANIMA 忽略了指令。设计不增加自动视觉归因或额外 LLM 分析作为回退前置条件。

### 通用检查

1. 更新提示词结果不满意，点击一次撤销回到更新前；重做可回来，不要求保存或采用。
2. 更新后已输入下一条意见，再撤销更新，下一条意见不丢失。
3. 改英文、改模型、恢复旧图分别可作为完整动作撤销，恢复范围与按钮说明一致。
4. 当前有未保存编辑与意见，点击旧图继续立即生效；点撤销恢复后，两者完整回来。
5. 通过修改意见和缩略图找到更早状态；恢复后后续历史及图片不被删除。
6. 没有图片的提示词更新也可以从创作记录恢复。
7. 仅查看旧图或查看记录差异，不改变当前提示词和生成条件。
8. 恢复时的 LLM 迟到结果和正在执行的生图任务均不覆盖新起点、不自动重复生图。

正常撤销只需一次点击；从已显示的旧图继续只需一次点击；更早内容通过“打开创作记录 → 定位并恢复”完成。恢复前后均无需额外保存或确认弹窗。
