# 个人标签超市设计

日期：2026-09-29

状态：用户于 2026-09-29 回复「嗯，就按这个开发吧」，书面设计已确认；实施计划待审核。

## 目标与已确认选择

在 ANIMA V3 内新增可独立维护的「个人标签超市」。用户沿用旧网站积累的分类和标签，日常快速找词、组合提示词，也能自由修改词库。旧网站不再使用，旧 PostgreSQL 数据作为一次性迁移来源。

采用已确认的两个视图：第一张效果图的分类选词布局，以及第三张效果图的表格管理和侧栏编辑布局。首版不制作第二张效果图中的大型组合编辑器。效果图中的示例分类数量、内容和提示词仅用于说明布局，实际页面以真实数据为准。

## 界面与主要流程

导航新增「个人标签超市」，路径 `/personal-tags`。沿用应用现有字体、主题、配色和控件风格，支持现有浅色、深色外观。

### 挑选标签

- 左侧为可展开的分类树，中间为双语标签列表，右侧为当前组合。中文名称优先显示，英文原文可见。
- 搜索中文名、英文内容和别名，可限定当前分类或搜索全部；分类筛选默认包含子分类。
- 点击明确的添加控件把条目加入组合。点击详情或编辑动作打开侧栏，不混淆编辑与选词。
- 切换分类、搜索、视图或刷新页面，已选组合都能恢复。
- 同一条目在同一正负区重复点击不会生成重复项；不同原始条目即使内容相近也不自动合并。
- 右侧分正向、负向两区，支持移除、调整顺序、移动正负向以及本次权重。提供按钮形式的排序方式，不只依赖拖拽。
- 下方实时预览最终正向、负向英文输出，可分别复制，或复制含明确 Positive / Negative 标识的完整文本。
- 可将当前组合保存为命名组合，下次加载后继续调整。保存组合保留条目内容快照，原条目后来编辑或删除不会悄悄改变已保存组合。
- 窄屏依次呈现分类、结果和可展开组合区，核心操作不依赖悬停。

### 管理词库

- 分类树、可搜索表格、编辑侧栏构成主要页面。表格展示中文名、英文内容、类型和分类。
- 新增及编辑标签可填写中文名、原始英文内容、别名、分类、类型、备注和个人默认权重。
- 类型为「单标签」或「提示词片段」。片段可以包含逗号和换行，保存与输出都保留内部文本结构。
- 支持多选后批量移动分类；批量操作完成后明确反馈成功数量。
- 分类支持新增、改名、排序和移动，禁止自身作为父级及形成环路。分类树按数据驱动，不把当前层数写死。
- 删除采用回收站。标签可恢复；非空分类必须先移动其标签和子分类，不能通过删除分类隐式删除内容。
- 相近词提示不阻断编辑，用户可决定保留不同条目或手动调整别名。首版不实现自动合并或自动清理。
- 编辑侧栏有明确的保存、取消动作；未保存修改离开时提示。保存后搜索结果和组合中的既有快照不混淆。
- 页内提供 JSON 导入导出和回收站入口，不增加全局设置页的复杂度。

## 内容、权重与输出语义

- 原始内容作为独立字段保存；搜索规范化键只用于检索，不用作条目主键，也不覆盖原文。
- 普通单标签与片段都作为一个可选素材，片段不按逗号自动拆分。
- 正负向属于一次组合中的使用位置，不要求用户复制两份词库条目。同一内容同时出现在正负区时提醒，允许用户保留。
- 本次权重默认继承新模块的个人默认权重，初始为 1.0。修改本次权重不写回词库。
- 权重必须是有限数值，范围 0.1–2.0，步长 0.05，可手输；1.0 输出原文，其他值使用明确标注的 ComfyUI 常见括号权重语法 `(内容:权重)`。片段加权作用于整个片段，预览必须完整显示实际输出。
- 不自动翻译、大小写转换、下划线替换、插入质量词或根据模型猜测内容。输出方式不保证所有模型都响应权重；如有不同目标语法，后续另加输出适配。
- 标签内容、别名和备注只作为文本处理，不能作为 HTML 或可执行内容。

## 工作台衔接

「追加到工作台」传递完整正负输出，而非把片段伪装成旧标签篮中的单标签。

1. 本地生成一次性传递记录，网址只包含记录标识，不携带提示词正文。
2. 进入当前工作台后，显示原有内容与拟追加内容的预览，由用户确认追加或取消。
3. 追加到当前英文正负提示词编辑区；不改模型、生成参数、原有要求或当前图片。
4. 保留原文和顺序，在非空文本之间加入可见分隔；不静默去重、重新编译或调用模型。
5. 成功保存为可恢复草稿后才消费传递记录，刷新或失败重试不能重复追加。
6. 追加后支持撤销这次操作。若追加后用户又编辑了正文，禁用快照撤销并提示「追加后已继续编辑，请在提示词中手动移除」，不能用旧快照覆盖新编辑。
7. 没有当前会话时创建新会话再预览；遇到正在生成、未处理建议、版本冲突或保存失败时保留传递记录，等待用户处理。
8. 复制始终是独立可用的出口；个人标签的浏览、管理和复制不依赖 LLM、参考数据包或远程生成服务就绪。

## 数据存储与旧库迁移

使用现有 `workspace_db` 同目录的独立 `personal-tags.db`，通过同源 FastAPI 接口访问。不修改只读参考数据包，不向 V2 旧流水线加入业务逻辑，不增加 PostgreSQL 常驻依赖。

数据实体包含分类、个人条目、命名组合、组合草稿、导入批次和数据库版本。每个条目有稳定独立 ID、创建/更新时间及回收站状态；组合条目保存来源 ID、内容快照、正负位置、顺序和本次权重。

旧库检查结果：容器 `pg-local`，PostgreSQL 15，数据库 `postgres`，数据表 `public.sys_tags` 和 `public.sys_categories`。共 11,473 条标签、174 个分类；208 对空格/下划线近似变体；362 条旧权重不等于 1；91 条包含逗号、换行或尖括号等内容，需要作为片段候选检查。

迁移约束：

- 通过只读导出生成版本化中间 JSON，保存在用户数据目录；不把用户数据库或完整导出提交进 Git。
- 完整保留原标签 ID、内容、中文名、别名、来源、分类文本、分类 ID、原权重和其他原始元数据，便于核对和重新整理。
- 当前所有标签的 `category_id` 指向根分类。8,040 条可按 `sub_category` 找到直接子分类，导入时仍需验证匹配唯一性；其余 3,433 条先尝试唯一完整路径匹配，仍不能唯一定位的保留在原根分类并标记待整理，不丢弃、不编造分类。
- 保留 174 个分类及其稳定父子关系；导入前校验缺失父级、环路和非法数据。
- 208 对近似变体全部保留，并在导入报告给出相近项数量。
- 91 条仅标记为片段候选，允许在导入预览中确认类型；不自动拆成多个标签。
- 旧 `global_weight` 原样保存为迁移元数据。新模块的使用权重先设为 1.0；用户可在导入预览显式选择将有效旧值用作个人默认权重，不能仅凭旧字段名推断用途。
- 显示预览报告：新增、已导入、无效、相近变体、待分类、片段候选和旧权重数量。实际写入为事务操作，失败不留下部分导入。
- 用来源标识与旧记录 ID 识别重复导入。默认跳过已导入条目，不覆盖导入后用户做的修改；报告跳过数量。
- 首次实际导入前备份已有个人库。原 PostgreSQL 数据保持可供核对，正常使用无需 Docker。

JSON 导出带格式版本，包含分类、条目、组合及必要来源信息。导入先验证再预览，版本不支持或结构不合法时给出可理解错误，不能覆盖现有数据。代码通过 Git 合并，个人标签数据通过导入导出迁移。

## 实现边界

后端新增独立存储、API 和导入工具；前端新增页面、选词组合、管理编辑与数据访问模块。仅在应用路由、导航和后端注册点做接入改动；工作台增加独立的原文传递处理，沿用现有保存和冲突处理。

避开当前参考案例库的未提交文件。实施时先确认隔离工作区安排，再做代码改动，不复制或覆盖原有未提交修改。

不纳入首版：独立网站、多用户权限、双向数据库同步、自动 AI 分类、自动权重推荐、标签配图图库、批量自动合并、单独的大型组合编辑器，以及自动提交生成任务。

## 验收条件

1. 关闭 Docker 后仍能启动模块、搜索、编辑、保存组合和复制输出。
2. 真实迁移后核对全部标签和分类，导入报告能解释待整理内容；重复导入不新增重复记录、不覆盖用户编辑。
3. 中文、英文和别名搜索均有效；分类筛选包含子分类，分页后无漏项和重复项。
4. 编辑、批量移动、回收站恢复、分类防环和失败回滚均有可复现验证。
5. 片段原文、括号、逗号、换行、正负向及权重在输出中符合上述规则，刷新后组合可恢复。
6. 命名组合和 JSON 导出导入保留顺序、快照、分类与原始字段。
7. 工作台追加先预览，既有正文和设置得到保留；取消、保存失败、刷新重试、冲突及撤销不会导致内容丢失或重复。
8. 后端重点测试、前端行为测试、类型检查和构建通过；实际浏览器验证找词→选词→编辑→恢复→组合→复制/追加的完整流程及窄屏布局。
9. 原有标签超市、参考案例库及工作台的相关回归检查通过。
