# LLM 画面设计辅助 · 2026-09-12

画面设计控件用于表达创作意图；采用后的选择先进入草稿，只有既有“更新提示词”动作才调用编译，生图仍需明确提交。它不调用经典工作台 `composition.py`，不展开旧预设、不静态拼 tag，也不改模型、种子、采样、LoRA 或自动补负向。

## 数据与表达

- 五项均默认“不指定”，支持自定义、逐项清除和撤销。景别、构图布局、相机机位、人物视线位于 `requirements.layers.composition.design`；氛围位于 `requirements.layers.lighting.mood`。
- 每项保存 `value` 与 `source`。来源区分用户指定、用户确认的原文提取、用户采用的助手建议。原文提取额外保留 `evidence` 原句；视线必须有明确 `target`，避免把一个人的视线分配给全部人物。
- 这些字段属于对应锁层。锁定阻止自动修改／建议采用，用户仍可主动手动调整。LLM `layer_updates` 不能写入或覆盖这些控制字段。
- 选择不删手写文本；已有自由文本景别与快捷选择不同时先要求明确确认替换，可撤销。其他构图／光影文字提供展开核对。LLM 若报告与独立手写要求的冲突，本轮结果不保存，等待用户处理。
- 编译保存 `scene_intent` 来源快照，下次编译会告知 LLM 哪些旧控制已替换／清除，从而与独立手写文本区别处理。新编译也保存排除层指纹；无新增对话且排除层未修改时，代码保持上次审核过的负向原文。
- 空设计和空可选字段从编译输入指纹排除，旧记录不会仅因新增字段而变为待编译。前端清理服务端的空默认值，保存之后不会产生虚假的未保存状态。

## 显式获取建议

`POST /api/v3/workbench/scene-advice` 接收会话 ID／revision，以及当前未保存的 requirements、delta、正负提示词。该路由需要当前本地会话，使用现有 LLM 设置；不保存会话、不修改要求、不提交 GPU。

结果最多三组有区别的建议，原文提取另列并保留可核对原句。两类结果都需用户明确采用。无效格式、找不到原文依据、缺失视线作用人物、修改锁层或覆盖已指定控制都会拒绝结果。请求期间会话／本地草稿变化会使旧建议失效；请求失败保留草稿。相关层全部锁定时不发起收费请求。

## 验证与边界

自动化覆盖默认无附加内容、互斥替换、清除／撤销、保留手写文字、视线归属、自定义、建议未采用不改变要求、锁层、失败与延迟结果、历史指纹、保存重开、参考 pin，以及编译时保留原负向。

本轮未进行真实 LLM 或云 GPU 请求。结构校验、引用原句核验、锁层与事务保护不等于自然语言语义已被完全验证；提示词是否准确协调构图／多人物关系，以及不同模型的画面响应，仍需要用户选定服务后的少量人工实测。
