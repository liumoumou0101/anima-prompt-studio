# Aesthetic 版本拆分验收（2026-09-11）

用户明确要求：Aesthetic v1.0/v1.1 像 Turbo 各版本一样独立选择，取消新操作中的模糊模型族选择。所有模型，包括 Turbo v1.1、MiaoMiao，均可按证据调整；它们仅是当前观察较正常的参照。继续处理遗留管线，不制作安装包。

## 变更

- 新选项和模型 ID：`ANIMA Aesthetic v1.0` / `anima_aesthetic_v1_0`；`ANIMA Aesthetic v1.1` / `anima_aesthetic_v1_1`。经典工作台、会话创作、英文直出及后端模型目录一致。新建/默认请求使用 v1.1。
- 两个版本各有 ModelProfile、RuntimeProfile 与对应打包工作流兼容声明。当前采样默认值仍均为 35 步、CFG 4.5、Euler/normal；拆分并不冒充已经找到各自最优参数，后续可以独立调整。
- 新操作隐藏旧 `anima_aesthetic_v1` 族选项。旧工作台/浏览器草稿通过其保存的服务器和工作流目标恢复具体版本；以服务器解析后的权重绑定为依据。找不到目标或不能唯一判断时显示“旧美学配置：请选择 v1.0 或 v1.1”，不能在模糊选项下直接生图。会话恢复后如模型身份发生变化，按正常保存/重新编译流程处理。
- 旧运行记录、冻结工作流和幂等回执不批量改写。旧族 ID 仅为旧数据/请求兼容保留，原图具体权重由原工作流决定；不把所有历史图片归为 v1.1。
- 后端兼容检查同时核对显式版本和已识别的权重文件。1.0 请求配 1.1 工作流、或已声明 1.0 的模板映射到已知 1.1 文件时拒绝。未知自定义文件不能仅凭猜测其名字宣称版本正确，仍需明确配置与文件身份核验。
- 导入工作流识别优先看模型加载器文件，避免旧显示名/提示词中的版本文本影响判断。旧参考资料的模型族兼容声明保留原有含义，具体执行工作流仍接受版本校验。
- 画廊兼容层能理解新的版本 ID，并按版本挑兼容目标，避免新 1.0 图片因旧工具不认识 ID 而报错或换到 1.1。此前审计发现的旧图完整工作流/LoRA 恢复与放大链问题尚未全部改造。
