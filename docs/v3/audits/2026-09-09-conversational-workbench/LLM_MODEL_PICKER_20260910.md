# LLM 模型目录刷新与快速选择

用户人工测试发现 OpenCode 套餐难以更新模型列表和快速选型。原界面仅展示本地预置模型的 datalist，没有目录刷新入口。

本轮增加“刷新模型列表”、名称搜索与明确的模型下拉选择；手动输入仍可用。选择后由“保存配置”生效，不暗中调用连接测试或生成接口。刷新失败保留旧目录与手动填写入口；未保存地址或 Key 时禁止刷新，避免误用旧密钥。

新增 `POST /api/v3/llm/services/{service_id}/models/refresh`，沿用会话和 Origin 校验。只使用已保存地址和 Key，OpenAI 兼容服务请求 `/models`，Ollama 请求 `/api/tags`。请求超时 20 秒、不跟随重定向，失败不回显上游正文。结果按名称去重排序并保存，保留现有模型参数、自定义模型与当前选择；请求期间服务地址、Key 或协议变化时拒绝写回。

真实 OpenCode 验证返回 36 个模型，当前模型不变，没有文本生成或 GPU 调用。相关后端回归包含保存 Key、模型参数保留、失败不写配置、请求期间服务变化及 Ollama 协议；前端全量 76 项、TypeScript 与生产构建通过。界面组件回归验证刷新、搜索、选择后显式保存及未保存地址拦截。

本轮产物版本升为 `3.0.0-alpha.2`，与旧人工测试 alpha.1 区分。目录返回不等于每个模型都有当前套餐生成权限；使用已有连接测试可单独验证所选模型。新刷新功能不会改变非思考模式配置。

最终验证：相关后端 25 项、前端全量 76 项通过。新冻结 EXE 经本地模型目录 HTTP 服务验证刷新与当前模型保留，网页资源、内置样例及笔记/工作台重启恢复也通过；报告 `.local/frozen-http-20260910-235511/report.json`。安装版沿用已验证安装脚本，重新构建为 alpha.2；本轮没有重复提交生图。
