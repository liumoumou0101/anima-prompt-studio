# ANIMA Prompt Studio 项目审查与开发建议

日期：2026-09-12。范围：当前未提交修改也包含在内的 V3 源码、正式 Web 构建、现有词库、案例资料、运行与发布路径。

结论：项目已经有可用的提示词、模型配置、工作流快照、生成与归档基础。下一阶段最有价值的是把资料、选择与创作连起来，修复日常使用和新机启动的断点，再统一主工作区的交互与视觉。不建议重新推翻整个生图引擎。

本次没有修改产品代码、正式数据库或云端软件，没有调用 LLM/GPU。浏览器使用当前构建与正式数据库的隔离副本，写入的测试会话仅在副本内。除会话入口外，UI 截图来自该隔离实例；临时维护隧道未启动。只读代码审查、数据查询和浏览器操作共同构成证据，不是完整安全审计或全功能验收。

## 3. 推荐补全：先提高输入效率，再做风格推荐

现有数据库可复用：52,475 个标签，其中角色 22,195、作品 5,664、通用 24,616；另有 24,636 位画师和 14,122 条标签别名。标签分类检索、画师搜索、题材画师推荐 API 已存在；主工作台也已有需展开并主动刷新的画师推荐面板。

三种需求要分开做：

1. **名称补全。** 角色、作品、画师输入时显示分类正确的候选；中文名、标准 tag、所属作品一起展示。支持键盘上下选择、Enter 接受、Esc 关闭、最近使用、收藏、粘贴多项和自由输入。输入法组词期间不打断，过期搜索请求不能覆盖新结果。选中后呈现可移除的标签，而不是把多个名字堆进长文本框。
2. **上下文辅助。** 选择角色后展示可能对应的作品供确认；限定某作品后缩小角色候选。避免自动加入服装、发色、画师或模型没有保证认识的新身份。第一版可只有已有词库、正式别名和用户自定义记录，不必依赖 LLM。
3. **画师与风格选择。** 名称补全帮助“我知道要谁”；按画面主题推荐帮助“我不知道用谁”。当前共现推荐反映题材，不等于笔触/用色/线条风格。应优先接入本地参考缩略图、用户实测样图与收藏，明确“为什么推荐”，点击后写入当前会话并允许撤销。

本次实测：混合角色/作品搜索“初音未来”，前三为 `vocaloid`、`hatsune_miku`、`project_sekai`；限定角色后初音排第一。“フリーレン”“ぼっち”没有结果；画师“藤ちょこ”没有结果，`fuzichoco` 有结果。`vocaloid.cn_terms` 包含“狗、初音未来、虚拟歌手”等噪声，说明关联词不能等同正式别名。补全排序应是标准名/正式译名/真实别名精确匹配优先，然后前缀，再关联词召回，热度只作辅助。

所有标签的 created_at 当前为空，数据包仅有 approximate 截止说明；这不能证明某模型一定认识某角色。建议分别显示“词库收录”“作者声称覆盖”“本模型实测”，未知项仍允许用户手输。模型知识提示后做，不能先包装成没有依据的识别概率。

复用点：[手动输入组件](H:/soft/提示词工具2/v3/web/src/components/ManualIdentityTags.tsx:12)、[分类搜索](H:/soft/提示词工具2/v3/src/anima_prompt_studio_v3/data/store.py:104)、[画师搜索](H:/soft/提示词工具2/v3/src/anima_prompt_studio_v3/data/store.py:558)、[现有画师推荐](H:/soft/提示词工具2/v3/web/src/components/ArtistRecommendations.tsx:13)。

## 4. UI：需要统一日常操作，而不只是换配色

“默认 AI 风格”是审美判断。当前截图支持的具体表现是：深色底、紫色强调、大块相似卡片、装饰性英文眉题、星光符号、巨大的空白区；画师页使用大衬线标题和文字卡片，会话页是另一套表单面板，参考页又接近默认表单。视觉语言和信息密度没有统一。

最值得调整的地方：

- **让工作区服务当前画面。** 缩短首次输入到可编辑画面的路径；提示词和结果对照占据核心区域，角色、风格、参考放在输入附近，模型与参数作为紧凑侧栏，对话修改记录可收起。当前空对话区最小高度 640px，挤占创作结果空间。
- **明确每一步唯一的主要操作。** 初次“整理要求”，修改后“更新提示词”，准备完成后“生成图片”。后台继续保留保存/编译/提交的可靠边界，界面不需要并列展示多组近义按钮。不要把原本明确分开的 LLM 改写和 GPU 生成合并为意外出图。
- **统一控件体系。** 同一字号层级、输入高度、边距、焦点、禁用态、提示位置和主次按钮规则；界面功能以清楚中文命名，移走不帮助判断的版本号和调试说明。保留必要的模型/资源差异说明。
- **让画师和参考有图可选。** 当前画师列表主要展示投稿量、关联标签和首字母装饰，难以判断喜欢哪种风格。可先接入已有本地案例和用户确认样图，减少装饰，提升对比效率。
- **减少嵌套滚动。** 当前右侧要求面板自己滚动，整页也滚动；角色/画师三框占据较大高度，底部动作与结果容易离开视野。保留固定位置的主要操作和当前状态，避免对每个子区都加滚动条。
- **补交互状态。** 搜索等待时区分旧结果与新查询，空库说明资料来源与下一步，连接失效提供恢复，复制/保存/带入后给出明确结果。不同页面的“带入”必须作用于同一个创作上下文。

可访问性方面：本次截图可见表单标签、页签和键盘焦点轮廓，已有良好基础；次级文字较小、部分按钮只靠低透明度表现禁用、内外滚动与图标点击区值得继续检查。本轮未测完整键盘流、200% 缩放、移动窄屏和对比度数值，因此不声称满足完整 WCAG 标准。

## 5. 分批开发与验收

| 批次 | 具体交付 | 完成条件 |
|---|---|---|
| A：补可靠性与流程断点 | 新机初始化、会话恢复、V3/前端 CI、标签带入新会话 | 空用户目录能建立首个连接；活跃超过一小时可继续；新 tab 能从可信入口恢复；标签类型正确、只添加一次且可撤销；push/PR 跑 V3 与前端 |
| B：把已有资料变成可用功能 | 导入 124 条参考，角色/作品/画师补全，最近使用与收藏 | 重复导入不重复；未知参数不伪造；关键词能找到已收录案例；选中身份写入正确字段；无词库项仍可手动保存；全键盘可用 |
| C：统一主工作区和视觉 | 主操作与状态整理、紧凑参数、参考/结果对照、公共控件规范 | 不依赖解释即可完成“选角色→选风格→写要求→看提示词→生成”；保留草稿、锁层和参数快照；宽屏/常用笔记本尺寸与缩放检查通过 |
| D：改善推荐质量与模型评测 | 样图支持的画师推荐，模型实测记录，固定样本对照 | 区分题材与风格证据；新增模型不会继承未经验证的 LoRA/配方；人工评测记录角色识别、构图、结构和风格各自问题 |

工程组织建议：复用现有 schema、ReferenceDataStore、案例 API、工作流目录与生成快照；建立一个共享的“向当前会话添加已选内容”契约，让标签页、画师页、补全、案例都通过它。按纵向流程改动，不先进行大规模目录搬迁。发布前再集中做空目录安装、升级和旧数据迁移回归。

跨电脑交接也应成为交付的一部分：明确代码版本、词库/模型/参考包清单、用户会话与案例导出位置；凭据继续使用本机凭据管理器。当前 `anima-ref/` 与 `.local/` 不会随普通代码同步，不能再把“文件在开发机上”当作用户已经能用。
