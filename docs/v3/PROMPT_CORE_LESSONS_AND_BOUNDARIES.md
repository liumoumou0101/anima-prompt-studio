# V2 提示词核心复盘与 V3 编译边界

状态：当前开发约束

更新时间：2026-08-27

本文回答一个容易反复混淆的问题：V2 已经完成了本地翻译、语义规则和结构化输出，V3 为什么不能直接复用，也不能只把本地翻译接到新标签库后视为完成。

本文与 `DECISIONS.md` 一起约束后续提示词核心开发。若较早的 README、状态文档或会话记录与本文冲突，以较新的架构决策和本文为准。

## 1. 结论

V2 的原始设计不是“把中文直接翻译成英文”。它设计的是一个混合编译器：

```text
中文原文
  → 专名保护、规范化和本地翻译
  → 回译与语义差异提示
  → 可标准化事实转成 ANIMA 标签
  → 复杂动作和关系保留为英文自然语言
  → 叠加人数、角色、构图、场景、风格、模型配置和增强规则
  → 输出结构化 PromptJob
```

这个方向比直接翻译更完整，但真实测试证明其核心抽象仍有问题：

1. 翻译文本不能可靠承担人数、否定、左右手、属性归属、接触关系和复杂事件。
2. 把人物、动作、场景和构图压成平铺字段，会丢失“谁对谁做什么”“谁实际可见”“哪个事件决定画面”等信息。
3. 默认构图、弱情绪、相关标签和增强模板会把程序推断伪装成用户事实，并可能让画面偏离原意。
4. 结构化字段通过 schema 校验，不代表结构忠实；提示词字符串通过单测，也不代表实际出图正确。
5. 继续增加词典、guard 和姿势特判可以修复已知用例，但会延续 V2 的耦合与维护方式，不能自然扩展为通用画面理解。

因此，V3 的正确方向不是复刻 V2，也不是退回直接翻译，而是：

> 将原文证据、画面事实、实体归属、关系、构图控制、模型渲染和可选推荐分层；任何自动结果都必须标明来源、置信度和是否由用户确认。

## 2. 历史演进与证据

### 2.1 V1/V2 初始设计：翻译只是入口

`ANIMA中文提示词辅助工具_V1正式设计方案.md` 已明确要求：

- 标签负责人数、外观、基础服装、简单姿势、场景和镜头等稳定概念。
- 英文自然语言负责左右手动作、多人互动、具体视线目标、空间关系和多动作过程。
- 无法可靠标签化的内容必须保留，不得因匹配失败而删除。
- 最终结果还受角色卡、LoRA、人数、构图、质量预设和模型配置影响。

所以“直接翻译”从来不是产品目标，只是语义保留通道之一。

### 2.2 首轮真实语义审计：翻译和早期结构同时失效

`reports/pre_fix_test_baseline.md` 记录的真实 Marian 基线为 33/76 通过：

| 失败族 | 观察结果 |
| --- | --- |
| 否定 | 0/10 通过 |
| 属性覆盖 | 1/6 通过 |
| 多人作用域 | 2/8 通过 |
| 动作 | 7/15 通过 |

同时存在：用户编辑英文仍被旧中文影响、角色卡属性与本次描述冲突、抱膝被弱化为 `hands on knees`、大量失败仍被差异检查标绿。

这证明问题不是简单“换一个更好的翻译模型”，而是翻译、事实表示、优先级、匹配和编译之间没有可靠边界。

### 2.3 V2 加固：有效，但主要是已知失败族的护栏

后续 V2 加入了大量真实有价值的能力：

- 概念强映射与更具体概念覆盖泛化概念。
- 否定、人数、视线、左右、属性冲突和用户英文权威处理。
- 视觉语义归一化、概念补全、标签噪声过滤。
- 动作、场景、构图和模型专用模板。
- 用户编辑、锁定和排除状态。

这些能力将确定性语义审计提高到全绿，并修复了许多实际问题。它们是重要的回归资产，但不能据此推出“V2 结构已经正确”：

- 审计主要判断提示词中是否保留预设事实，不等于图片是否正确执行。
- 大量修复通过特定词典、guard 和模板完成，对新组合和长叙事的泛化能力有限。
- 自动增强、默认构图和标签拼接仍可能在字符串正确时改变画面重心。

### 2.4 复杂小说实测：平铺结构无法表达决定性画面

`reports/novel_complex_3x3/assessment.md` 的三组固定参数实测中：

- 双刀交锋、刺剑、撑地踢等决定性动作在提取层被丢弃，3 张均退化为站立、牵手或舞伴动作。
- 背后说话的人被错误当作画面中第三名可见角色。
- 两军对峙的属性被扩散到全体人物，空间对峙变成正面合影。

根因不只是翻译漂移，还包括可见性、事件优先级、关系、区域、实体属性所有权和构图策略缺少可靠表示。

### 2.5 冻结画面计划：证明“更合适的结构”有用，也证明纯文本有边界

`reports/novel_complex_final_3x3/assessment.md` 将一键编译改为独立冻结画面计划、不再经过旧 Marian 多人翻译后：

- 双人撑地反击踢与双刀从 0/3 提升到 3/3 近似命中。
- 左右两军与中间人从 0/3 提升到 3/3。
- 森林救援的人物保护关系达到 3/3，但两把旋转飞刀仍为 0/3。

这说明一个主动作或一个清晰区域布局可以通过更好的画面计划改善；同时要求人物接触、投射物轨迹、怪物受击和环境破坏时，纯文生图会继续融合事件。此类场景需要风险提示，未来可能需要区域提示、姿势/深度控制、分层生成或后期合成。

### 2.6 最近 V3 实测：两个极端都不成立

最近的 V3 远程报告再次否定了两个极端方案：

1. **AI 结构化抽取不是稳定默认入口。** 单次常见 50～100 秒；同一输入可返回数组代替字符串、契约外枚举值，或丢失风格、构图和小道具。
2. **翻译加精确标签也不是完整候选。** 当前本地路径只做中文/英文 n-gram 精确索引，Literal 会非常稀薄；完整译文只能作为 Hybrid prose 保留。

例如当前 `_local_natural_intent()` 会把精确命中的 canonical tag 全部标成 `required`，最多按热度保留 40 个；这无法区分完整概念、偶然子串、用户事实和低价值命中。当前 `add_conservative()` 又会把共现结果直接加入 Conservative，仍存在语义漂移。

所以本地翻译路径只是当前可靠性更高的保底入口，不是最终提示词核心设计。

## 3. 必须避免的错误结论

### 3.1 “V2 有很多规则，所以整体复用 PromptPipeline”

错误。V2 `PromptPipeline` 把翻译、语义帧、概念、增强、标签、构图和编译紧密串联，正是 V3 要拆开的中轴。可复用的是经过证据验证的局部能力和测试案例，不是整条控制流。

### 3.2 “本地翻译实测比 AI 抽取好，所以直译就是主方案”

错误。该结论只表示当前本地翻译比不稳定 AI API 更适合作为默认、快速、不会清空工作台的入口；它不表示直译能正确处理关系、属性所有权、事件优先级或 ANIMA 模型偏好。

### 3.3 “增加更多结构化字段就能解决问题”

错误。结构字段必须对应可观察的画面控制，并保留原文证据。错误抽取出的完整 JSON 比可编辑的未命中更危险。

### 3.4 “标签越多、共现分越高，提示词越好”

错误。共现只说明数据关联，不说明用户意图或画质收益。`snow → snowman/christmas`、物体词误命中和属性扩散都属于已知反例。

### 3.5 “自动测试全绿就代表提示词核心完成”

错误。静态测试是提交前门禁；最终结论必须来自固定模型、参数、工作流和 seed 的真实图片对照。

## 4. V3 必须显式考虑的因素

| 因素 | 要回答的问题 | 失败时的典型后果 |
| --- | --- | --- |
| 原文证据 | 结论来自哪段原文、用户编辑还是程序推断 | 无法解释或撤销错误 |
| 可见实体 | 哪些人物/物体实际应出现在画面 | 对话人物被画出来、人数错误 |
| 属性所有权 | 发色、服装、道具属于谁 | 群像串色、服装扩散 |
| 主动作与关系 | 谁对谁做什么，接触点和方向是什么 | 互动退化为并排站立 |
| 事件预算 | 哪一个瞬间最重要，哪些事件只是背景 | 关键武器/动作被裁掉 |
| 空间与区域 | 左/中/右、前/中/后、上下关系 | 对峙变合影、主体融合 |
| 镜头与视线 | 景别、角度、方向、主体位置和是否看镜头 | 默认正面居中覆盖原意 |
| 风格意图 | 二次元、立绘、赛璐璐、线稿、视觉主图等 | 事实保留但画风错误 |
| 模型配置 | Base/Aesthetic/Turbo 如何渲染质量词和参数 | 正确内容用错模型语法 |
| 表达载体 | 某事实应使用 tag、短语、句子还是控制能力 | 复杂动作被弱标签替代 |
| 排除与冲突 | 用户明确不要什么，哪些事实互斥 | 正负同时出现、删除项复活 |
| 推荐隔离 | 哪些内容只是标签/画师/审美建议 | 自动扩展污染基准 |
| 可实现性风险 | 纯文本和当前模型是否能承载该场景 | 对不可控任务做虚假承诺 |

## 5. V3 目标边界

V3 不应让任一解析器直接产出“最终正确结构”。推荐分为四层：

```text
Source Evidence
  原文、译文、用户编辑、命中片段

Scene Draft
  可见实体、明确属性、主动作、关系、场景、构图、风格、排除项、风险

Mapping Review
  已确定映射 / 可选建议 / 未命中内容 / 冲突

Prompt Candidates
  模型专用 literal baseline / 用户选择后的增强 / 可选画师 / prose hybrid
```

关键规则：

1. `Source Evidence` 不可被自动结果覆盖。
2. `Scene Draft` 必须允许部分完成；未知比错误补全更安全。
3. 只有用户明确内容或可证明的确定性映射可进入 Literal。
4. 翻译全文可作为可编辑 prose baseline，但不能自动证明其中每个 tag。
5. 语义匹配、共现、画师和风格补全全部进入建议层，默认不改变 Literal。
6. 用户选中或取消建议后，只重新映射和渲染，不重新翻译或重新解析。
7. 高风险复杂场景必须显示能力边界，不通过堆叠更多提示词伪装成已解决。

## 6. V2 资产的处理方式

### 6.1 可直接复用

- SSH、ComfyUI、队列、凭据、工作流渲染、结果归档和画廊。
- 本地 Marian 加载与离线翻译服务，作为可编辑译文来源。
- 模型配置与生成参数合同，经过 V3 renderer 适配。
- 真实测试用例、失败族、固定 seed 和历史报告。

### 6.2 可选择性迁移，但必须独立验证

- 专名保护、否定检测、人数识别、用户英文权威和冲突优先级。
- 已有概念映射、视觉语义归一化和少量动作模板。
- 标签噪声过滤与 canonical 规范化。
- 冻结画面计划中被真实图片证明有效的区域和主动作表达。

迁移要求：通过 V3 adapter 或独立纯函数接入；必须有原文证据、失败族回归和 V3 类型，不得导入旧 `PromptPipeline` 控制流。

### 6.3 冻结为对照，不作为 V3 权威

- V2 `PromptPipeline` 和 `PromptCompiler` 的完整主链。
- 平铺 `SemanticFrame` 作为完整画面真相的假设。
- 默认弱情绪、默认看镜头、默认正面居中等创作性补全。
- 自动把所有标签命中、共现标签或画师写入最终提示词。
- V2 `AIExtractService` 当前返回合同作为默认自然语言入口。

## 7. 下一开发切片

在继续扩标签池或画师选择之前，先完成一个不依赖远程生图的“输入证据到可编辑草稿”切片：

1. 从历史失败族选择 8～12 个代表案例：单人立绘、单人复杂动作、明确否定、持物/左右手、双人关系、风格要求、静态群像和超能力边界案例。
2. 定义最小 `Scene Draft` 合同，只包含这批案例真正需要的可见实体、明确事实、主动作/关系、构图、风格、排除项和风险；不提前设计万能 schema。
3. 本地翻译始终保留为可编辑 prose baseline；没有 tag 命中也必须成功返回，不能 422 或清空上次结果。
4. 将当前精确命中拆成“确定映射”和“待确认匹配”；禁止按热度截取后全部标成 required。
5. Conservative 共现改成默认未选建议；用户选择后本地重编译。
6. 对该切片运行静态保真门禁，再用固定 Aesthetic v1.1 参数做首轮真实图片对照。

当前进展：Scene Draft 已将正向证据、明确排除、建议和未命中分开，并允许编辑英文画面计划后只重新映射。Literal 已开始按参考数据能够证明的事实类型稳定排序；未分组标签保持“尚未归层”，不通过新增关键词规则假装理解。可见实体锚点和人工确认的属性归属已经进入合同，但归属不会擅自改写提示词；首个 `wearing` 关系也必须在归属确认后再次确认，只影响 Hybrid。下一切片仍需处理主动作/对象关系、事件预算和多实体区域，不能把当前标签分层或单主体建议误认为完整画面理解。

该切片的目标不是一次解决任意中文，而是证明新的边界能避免 V2 已知错误，并为后续人物、动作、风格和画师能力提供稳定接口。

## 8. 验收原则

- 无精确 tag 命中时仍返回可编辑结果。
- 原文、译文和上次成功候选在任何解析失败时都不丢失。
- 每个进入 Literal 的事实都能追溯到用户证据或明确锁定。
- 建议项在用户选择前不改变任何候选。
- 删除或排除项不会在重编译时重新出现。
- 静态测试至少覆盖人数、否定、属性归属、动作主体、构图、风格和未命中。
- 真实生图采用固定模型、工作流、参数和 seed；字符串变好不能替代图片证据。
- 对纯文生图能力外的复杂事件链，结果必须标记风险而不是宣称已解决。
