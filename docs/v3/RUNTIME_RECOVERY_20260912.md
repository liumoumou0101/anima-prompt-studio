# 本地运行与会话恢复

2026-09-12。本轮只调整可靠性与验收路径，不改变主工作台视觉。

- 桌面启动器接收运行库路径后会自动创建数据库。旧库继续沿用原路径与兼容 schema；新机不必先安装或运行 V2。仅 `--without-runtime`（兼容旧名称 `--without-v2`）明确关闭生成服务。API 开发启动器默认在工作台数据库旁建立 `runtime.db`，也可指定 `--runtime-database`。
- 桌面本地端口保存在工作台数据库旁的 `<数据库文件名>.local-api.json`，格式为 `{"schema":"anima-local-api-port/1","port":9534}`。首次随机分配，后续优先使用上次端口，让同一个浏览器 origin 的草稿、偏好和最近选择在重启后仍可读取。状态原子写入，非法状态忽略；端口占用时安全切换随机端口并记录明确提示，不抢占其他应用。Windows 使用独占绑定。独立 API/测试服务器默认仍随机。
- 会话改为一小时无 API 活动才过期；有效调用会续期。在服务仍运行、同一个浏览器配置和同源地址下，新标签页、关闭浏览器后重开及闲置过期都可自动恢复。恢复不刷新整个页面，原请求体和幂等键保持原样，只在认证失败且业务路由尚未执行时重试一次。
- 恢复凭据只通过已验证的一次性桌面 bootstrap 或有效旧会话发放，保存在按协议、主机和端口隔离的 localStorage。服务端只存哈希，最长 30 天无恢复活动过期；服务退出后全部失效。恢复端点不是无凭据入口，不接受图库 cookie 作为恢复凭据。
- 写请求必须有完全同源 Origin（包括端口）与正确 Content-Type。维持 loopback Host 限制、不开放 CORS；图库 HttpOnly/SameSite=Strict cookie 使用每个服务实例独立名称，防止多端口实例覆盖，而且只携带独立的图库读取凭据，不能用于 API bearer、写操作或恢复。已有 bearer session header 仍可用。Vite 代理保留原始 Host，让开发模式遵守同一规则。
- 初次连接或恢复暂时失败时，启动页可以重试。未交换的 bootstrap 仅在当前页内存中保留用于网络重试，地址栏立即移除凭据。恢复不会清除其他本地草稿。

保留端口只保留浏览器地址，不延续已经退出的服务会话。重启服务后仍需使用桌面启动器新发放的 bootstrap；不会从端口回执恢复凭据，也不会跨端口共享会话。

## 持续验证与发布

push/PR 工作流同时安装旧运行依赖和 V3 测试依赖，运行 `tests` 与 `v3/tests`；独立前端任务执行 Vitest、TypeScript 检查和 Vite 构建。Windows 发布也显式安装测试依赖，并先通过前端测试和构建。

发布程序烟测使用全新、独立目录，启用实际 runtime。新增 `--verify-runtime --no-browser --exit-after-startup` 会经由真实 localhost HTTP 验证 bootstrap、生成服务可用和首个连接的创建；只创建禁用的本地测试连接，不调用 GPU/SSH。该模式拒绝已有运行库。二次启动仍检查词库与参考包指针没有变化。

验收覆盖在 `v3/tests/test_session_recovery.py` 和 `v3/web/src/lib/api.test.ts`：超过一小时持续活动、闲置后恢复、跨端口/恶意 Origin 拒绝、无凭据拒绝、图库 cookie 不能恢复、实例隔离、旧会话升级、同源恢复、多请求共享恢复、幂等写重试、网络恢复，以及全新数据库建立首连接。
