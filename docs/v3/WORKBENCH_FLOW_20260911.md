# 工作台创作流程第一轮改进

日期：2026-09-11。用户授权继续；范围为工作台要求、提示词、参数和历史结果之间的衔接，仍离线开发。

## 本轮完成

- 工作台顶部明确展示当前画面要求、提示词、生成条件的状态，区分待发送想法、要求/模型修改、手改提示词和仅采样参数修改。
- 保留“保存要求与设置”，增加一步完成的“保存并编译提示词”及“整理新想法，更新提示词”。先以版本检查保存要求，再用新版本编译；失败时保留本地输入。编译成功后切到提示词页签，不自动生图。
- 新空白会话可以直接在要求页填写内容，再保存并编译，不必先走自然语言追加。已有内容且要求没变时禁用无意义的重新编译按钮，避免触发空修改报错。
- 仅修改尺寸、步数、CFG、种子、采样器等参数，保存后保留现有编译状态、提示词和令牌，无需调用 LLM。后端本来已有此语义；修复的是前端提示和旧测试中“一律模拟失效”的错误假设。
- 最近一次成功整理后，可展开对照整理前后的正负提示词。对照是本次操作的文本快照；之后手改输入框不会改变对照内容。完整历史版本存档、逐词差异和撤销尚未实现。
- 从初始想法创建会话时，自动以想法前 40 字命名，便于在会话列表中辨认。
- 结果区改为按批次选择并展示当前批次，保留原图预览、收藏和任务入口；只挂载所选批次的图片列表，减少同时加载全部历史结果。生成请求被接受后滚动到结果区。
- 新增“沿用本次条件，新建会话”：直接从所选历史任务创建工作台，无需先收藏案例。继承任务的提示词、采样参数、精确种子、LoRA 与原工作流来源；当前工作台和浏览器草稿保留，不自动出图。
- 原任务目标不可用时，提示恢复执行环境或解除快照后换目标，不再引导用户操作被锁定的选择框。
- 结果列表读取失败显示可重试操作，仅重读图片接口，不重复生成。

## API 与数据

新增 POST /api/v3/generation-runs/{run_id}/workspace，JSON 请求体为 {}，不接受客户端提供生成快照。复用案例库创建生成来源工作台的内部逻辑；来源不存在时不创建空会话，也不产生案例记录。现有 generation_source 保护、版本检查及提交幂等机制保持有效。

这是开启新的创作分支，不是就地覆盖工作台，也不承诺不同环境/资源变化后像素级复现。完整工作流仍依赖本机持久化生成记录，资源可用性继续由既有解析和预检检查。
