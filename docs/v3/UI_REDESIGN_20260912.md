## 产品定位：LLM 辅助用户设计画面

用户进一步确认：当前主线是 LLM 会话工作台。景别、构图、视线和氛围等控件用于帮助用户表达、检查和调整创作意图。早期工作台未达到用户预期且细节实测较少，不能用旧界面或旧自动化测试推断新流程的创作效果已合格。

主流程为：自由描述／借用参考 → LLM 整理画面要求 → 用户通过文字或快捷选项调整 → 明确点击更新提示词 → 检查结果 → 明确提交生成。熟悉提示词的用户继续可以直接编辑；不要求先填完一套表单。

- 快捷选择进入结构化创作要求，由 LLM 与全文、角色关系和其他约束一起组织表达。此前“选什么加入什么”指的是忠实保留用户指定的语义，不要求所有选项一对一变成固定 tag 或直接拼接到正向末尾。
- 用户明确选择的内容标为已指定；从用户原文明确提取的内容保留来源；LLM 自行提出的构图或氛围建议单独显示，采用前不冒充用户选择。信息不足时保留不指定，不为了填满控件而猜。
- LLM 可以在用户请求帮助设计时给少量有区别的方案并说明取舍。日常只想执行已有想法时不强迫经过建议或问答流程。忠实还原与用户主动允许的扩写范围保持可辨认。
- 明确的角色／作品／画师 tag 继续准确保留；景别、空间布局和氛围由上下文表达。锁定、主体数量、动作归属和用户选项是模型必须遵守的要求，但不宣称已能用代码完全验证自然语言语义或保证生图服从。
- 选择控件先更新草稿，不因每次点击就自动请求 LLM，更不直接提交 GPU。使用既有更新入口一次处理本轮调整，并保留原文、前后结果及撤销机会；LLM 失败时不丢选择。
- 相机视角／景别属于画面描述；宽高、采样步数、CFG、种子属于执行参数。两个区域分别表达，前者不会暗改后者。
- 重新测试“自然语言→要求→快捷修改→提示词→实际图片”整条路径，特别检查原文与选项同步、重复描述、旧要求残留、多人物归属、锁层、自由扩写边界及失败恢复。界面测试通过与提示词语义正确、生图效果符合预期分别记录。

## 快捷画面控制：重新实现的边界

这一节取代此前“可复用／迁移旧构图模块”的建议。旧代码只用于发现过去的需求和失败场景，不用于证明参数、标签或模型先验正确。用户反馈 V2 效果未达预期，应以新功能实际输出和人工对照为依据，不以实现者使用的模型名称或能力作为质量保证。

- 分别定义景别、构图布局、相机角度、人物视线和氛围。人物“看向远方”不能无条件简化为“不看镜头”，机位俯视不能混同人物低头。
- 每项默认不指定，允许清空和自定义；用户选择哪些内容，就记录哪些内容。不给空选项补旧模型先验，也不自动附加画师、质量词、负向提示词或 LoRA。
- 建立独立的选项与语义模型、变更及撤销规则、提示词表达层；不调用旧 `composition.py` 的推断、预设展开和冲突补词逻辑。规范 tag 可以经核对后使用，不能因旧代码出现过就认定表达可靠。
- 结构化选择是可追踪的用户要求。界面能显示本次实际加入／替换的内容；重复切换不残留互斥选项，清空不会误删用户独立写入的文本，保存重开仍保留原选择。
- 与手写要求矛盾时明确提示并由用户决定，不暗中覆盖。多人物的视线或姿态必须明确作用对象；无法表达清楚时保留自由文本，不强套单人物预设。
- 接入当前已验证的保存、锁层、编译、生成快照和重试接口；重写范围是画面快捷控制及其提示词表达，不因此重建运行队列、凭据或连接管理。
- 验收先检查状态与最终提示词：选项生效、替换／移除正确、无额外补词、原负向不变、草稿与原任务快照不被破坏。再以少量固定场景、固定种子的模型对照判断实际画面响应，按模型记录结果，不把一次有效包装成普遍结论。

- 日夜切换使用相同的布局、滚动位置、输入内容和焦点顺序；布局选择独立于浅色／夜间／跟随系统。记住显式选择，首屏加载时避免先闪另一种主题。

- 分隔线用于组织内容；需要看清轮廓的输入框不能只依赖过暗的装饰分隔色。
- 禁用与只读分别表达，说明文字保持可读；不通过整体降低透明度让按钮及其原因一起看不清。

- 补全列表、弹窗、下拉、提示消息、复制反馈、图片预览遮罩均覆盖主题，不留下亮白弹层或旧紫色状态。
- 提示词使用清晰的非纯白正文、足够行距；画面预览区本身的中性背景不改变图片像素。透明图棋盘格单独定义，不能通过给图片上滤镜实现夜间效果。

## 共同的界面规则

- 默认浅色；提供浅色／深色／跟随系统设置，并在主界面保留容易找到的切换入口。深色采用中性炭灰，沿用所选方向的克制强调色，不使用紫色或霓虹效果。
- 移除背景网格、发光点、大字英文装饰、过多圆角卡片和空白聊天占位。优先用对齐、间距、字体层级和细分隔线组织内容。
- 正文 14–16 px，主要标题约 22–24 px，基础间距以 8 px 为单位。延续现有中文字体与 Phosphor 图标，不引入多套图标或装饰字体。
- 角色、作品、画师入口放在创作内容附近，已选项清楚显示、可逐项移除。名称补全与按题材推荐保持各自含义。
- 正向提示词可直接编辑、复制；负向提示词可以折叠，明确“未使用”，不能因为界面变化自动补入。
- 结果区显示原图、最近结果和适量评价操作。参考与画师页面使用可浏览的缩略图，来源和依赖放详情；表单与大标题不再抢占首屏。
- 生成条件中常显模型、兼容工作流／配方、尺寸、数量；采样器、CFG、LoRA 等逐步展开。当前编辑条件与历史图片的实际条件分别标明。
- 空态、等待、重连、保存、失败、未发送修改和参数变更均有明确文案。重要冲突持续显示，不用瞬间消失的消息替代处理入口。

## 必须保留的行为约束

1. “更新提示词”调用 LLM；“保存”只保存；“生成图片”才提交 GPU。可以随状态变化突出当前需要的按钮，但不得把这些动作合并成一个含糊的按钮。
2. 区分未发送想法、要求待编译、仅参数待保存和提示词已手动修改。只改尺寸或种子不应触发 LLM，也不能覆盖用户手改的提示词。
3. 模型、目标、工作流和配方切换继续按现有兼容规则联动。切换后展示所用配方；手动改采样参数时显示“自定义”。视觉改版不改默认参数表。
4. 从原任务沿用的快照须显示来源与锁定原因，并有明确解除入口。不能悄悄换成当前模板。
5. 标签带入仍区分当前会话和新会话，成功后可撤销；切页、刷新、重连、失败重试保留草稿和原提交语义。
6. 参考案例继续区分借用原提示词、借用要求、沿用完整生成条件。未知参数保持未知，借用提示词不自动启用 LoRA。
7. 历史图片、收藏、人工观察和沿用条件始终绑定当时任务；不能把当前编辑参数当作那张图的原参数。
8. 布局变动不得破坏输入法、键盘补全、可见焦点、控件标签、未保存提醒和版本冲突处理。锁定层仍只阻止自动改写，用户主动编辑可修改。

## 落地顺序

1. 依据已确认的两套工作台方向整理共享功能区和业务状态，先用一个完整场景验证编辑、选角色、查看图片与核对参数是否顺手。
2. 建立两套布局的浅／深色变量与共享基础控件，清理现有硬编码深色。避免只改顶层颜色导致输入框、弹层或选中态残留旧主题。
3. 实现工作室／编辑台布局切换与独立的明暗设置，保留同一业务状态及 API 边界；再统一参考、画师、标签、画廊、设置和工作流页面的主题。
4. 四种组合分别检查空态、加载、错误、恢复、生成中、完成等状态，并检查切换过程保留内容，最后运行原回归与浏览器交互验收。

## 视觉验收条件

- 在 1440 × 1024 和常见 1280 × 800 窗口中，主要动作可找到，字段不会互相挤压；较窄窗口将次要参数收进抽屉，避免三列硬挤。
- 浏览器 200% 缩放后内容可以重排或顺序阅读；文字不截断关键含义，焦点不会被固定操作条挡住。
- 文字、边框、焦点和控件状态的对比度实测后再判断可访问性；概念图不代表已通过检查。
- 图片保持比例，可看原图；对图像本身不叠加主题色或滤镜。浅色与夜间模式下均需观察不同明暗图片。
- 深色／浅色切换覆盖弹层、补全、按钮、输入框、禁用、错误和选中态，且记住用户选择。
