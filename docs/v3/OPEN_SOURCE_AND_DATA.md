## 3. pipeline 边界

`danbooru-tag-pipeline` 的角色是外部数据工厂，不是 V3 依赖包：

- V3 仓库不包含其源码或改写副本。
- 安装程序不自动下载或执行它。
- V3 CI 不 clone 后运行它。
- 文档只描述兼容的输入字段和用户如何向导入器提供产物。
- V3 自有导入器、校验器、manifest 和 SQLite 构建逻辑从零实现。
- 若维护者以后增加明确许可证，可通过新的决策记录重新评估。

公开发布官方数据包前，应确认运行该工具所得数据的再分发权；不能仅凭工具仓库公开就推定数据可任意再许可。

## 4. 代码与数据分开

GPL-3.0 适用于 V3 代码，不自动决定以下内容的许可：

- Danbooru 标签、别名、Wiki 文本和统计数据。
- Bangumi 返回的数据。
- LLM 生成或修订的中文说明。
- 在线预览的投稿图片。
- ANIMA 模型权重。

参考数据包使用独立 `NOTICE.txt` 记录来源、生成日期、构建方式、上游 commit、许可或未知状态。不能在没有依据时把整包标记为“GPL 数据”。

## 5. 在线图片预览

- V3 发布包不内置 Danbooru 投稿图片。
- 只有用户打开详情或预览时才请求远程内容。
- 默认关闭 NSFW 预览；文本标签的未知 NSFW 状态不按安全处理。
- 缓存限制在用户数据目录，提供容量上限、清理和关闭缓存选项。
- UI 显示来源链接和必要的作者/站点信息，不把缓存描述成项目自有图片。
- 不建立官方公共图片代理服务；本地客户端只代表当前用户访问。

## 6. 模型与翻译资源

ANIMA 权重不随 V3 再分发。V3 只保存逻辑模型配置和用户远程路径映射。Helsinki-NLP 翻译模型继续按各自模型仓库许可和当前 `THIRD_PARTY_RESOURCES.md` 处理。

如果增加 embeddings 或语义模型数据包，必须分别记录：

- 模型权重许可。
- 生成 embeddings 的输入数据来源。
- 是否允许再分发派生向量。
- 下载大小、哈希和版本。
