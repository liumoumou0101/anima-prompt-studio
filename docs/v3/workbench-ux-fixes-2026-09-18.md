# 工作台修改确认、版本回退与本地恢复

本轮修复解决修改直接覆盖提示词、手工提示词无法独立保存、历史难以回退及多个窗口草稿互相影响的问题，并补齐图片比较和工作流选项的操作细节。

## 主要变化

- 模型改写先显示候选和差异，用户采用后才写入当前版本；保留警告、不采用和重试操作。
- 手工正负提示词可独立保存；按英文提示词整理中文要求时保留英文原文，并先展示候选。可固定具体正负提示词片段。
- 保存和采用修改后保留版本快照；恢复产生新版本，也可从指定版本另开会话并追溯来源。
- 明确本地草稿与服务端保存状态，提供字段级冲突合并。每个页面独立保存草稿，并保留未知结果请求的原标识及内容。
- 新增本地草稿预览、恢复与导出入口；恢复前备份当前编辑。存储读取或备份失败时阻止自动覆盖。
- 固定单张图片作为对比基准，按会话保存在当前浏览器；刷新和重开后恢复原图。显示生成参数差异并支持沿用记录参数。
- 单个生成批次接口返回已保存的版本来源及提交参数，避免旧基准刷新后丢失这些信息。图片加载失败后可单独重试。
- 内置工作流采用中文类型、基础版或实验版说明；保留用户模板名称。同名模板和同名服务器具有可区分的标签。

## 验证

- 前端完整回归：47 个文件、403 项通过。
- 后端完整回归：932 项通过。
- TypeScript、Node 22 生产构建及 `git diff --check` 通过。
- 本地浏览器验证草稿预览、恢复前备份、刷新后的图片基准、会话隔离和工作流标签。
- 此前以两张固定种子图片验证真实生成、提示词修改和版本关联。本轮本地收尾未提交新的生图任务。

现有 AnyIO 弃用提示和前端包体大小提示不影响上述检查通过。

## 保留边界

- 本地清理仅整理确认重复的独立备份，不按时间删除其他窗口草稿、独有内容或待确认请求。
- 对比基准和本地草稿保存在当前浏览器，不提供跨设备同步。
- 图片的批次种子不等于所有工作流每张图片的实际种子。相同提示词和记录参数也不保证画面细节不变。
- 片段固定检查文字存在，不提供完整语义冲突检测或画面身份保证。改写模型尚不支持直接理解当前图片，也不将任意自然语言历史指代视为精确版本选择。
- 真实生成中断恢复、完整键盘操作、读屏和缩放验收留待后续。

## 人工测试建议

1. 在版本历史中另开测试会话，依次尝试手工保存、候选采用、不采用及旧版恢复。
2. 修改提示词后刷新，再次修改并通过“找回本地草稿”恢复旧内容，确认恢复前编辑仍有备份。
3. 固定已有图片为基准，刷新并切换会话，确认基准及参数恢复正确；清除后刷新应保持清除状态。
4. 检查基础版、实验版、用户模板和同名连接是否容易区分。
