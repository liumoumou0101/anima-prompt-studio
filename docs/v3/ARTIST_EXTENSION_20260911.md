# 工作台画师推荐扩展与轻量翻译

日期：2026-09-11。用户授权继续原开发路线；本轮不需要云显卡。

## 已实现

- 在会话工作台增加“画师推荐（可选）”面板，默认收起。只有展开时才读取推荐偏好，点击刷新才查询推荐；收起后卸载面板并取消未完成请求。
- 三种模式直接在工作台切换：题材贴合、投稿量优先、题材与投稿量均衡。沿用现有本地关联数据与排序算法，没有新增机器学习模型，也未把模式称为画质升级。
- 第一次推荐后切换模式会重新查询；使用 AbortController 丢弃被替代的响应，防止较慢的旧请求覆盖新模式结果。编辑依据标签立即清除旧名单。
- 从当前正向提示词读取逗号/换行分隔的标签，可以手动调整；去掉明确的画师/LoRA 指令，识别简单权重括号，最多使用 50 个标签。完整自然语言句子不会自动翻译或拆解成可信标签，未命中时提示调整。
- 每次显示最多 12 位画师，展示命中标签、历史作品量和详情链接。投稿量优先的含义仍是先按作品量/场景共现阈值筛选，再按题材排序。
- 只有“加入画面要求”才改变工作台的画师要求；不立即修改提示词、不调用 LLM、不生成图片。保留现有画师，规范化比较避免重复添加，最多 32 位。支持明确移除单个选择。
- 选择保存在原有工作台浏览器草稿里；收起面板、切换排序或切回工作台不丢失已选画师。推荐模式在当前浏览器记住；首次使用可读取既有服务端排序偏好，之后请求显式传递模式。
- 设置页不再放置三组排序单选控件，改为工作台入口；不再因读取画师偏好影响远程连接设置加载。旧排序 API 保留兼容用途。
- V3 翻译适配器固定使用 BuiltinOfflineEngine，不再探测 ResourceManager 模型目录、检查神经翻译依赖或构造 LazyLocalMarianEngine。旧工厂参数保留兼容，用户本机模型目录不删除。隐藏经典工作台的翻译说明改为词典，不再展示 Marian 选项。

## 实测资源

Windows、Python 3.12.2、当前真实参考数据包；使用独立数据库启动完整本地 API 服务，未配置云主机。内存来自 Windows GetProcessMemoryInfo，耗时来自与推荐 API 相同的 ReferenceDataStore.recommend_artists 查询路径。

| 场景 | 后端工作集 | 私有提交量 | 查询耗时 |
| --- | ---: | ---: | --- |
| 初次服务启动 | 88.14 MiB | 66.85 MiB | 启动约 1.19 秒 |
| 三标签，三种模式各 6 次后 | 89.33 MiB | 68.35 MiB | 首次 87 毫秒，预热后中位约 8.4～8.5 毫秒 |
| 独立进程，50 个高频标签，三模式各 5 次后 | 92.80 MiB | 72.25 MiB | 各模式中位约 102 / 104 / 118 毫秒 |

50 标签测试的工作集峰值约 96.12 MiB。两次运行都在词典翻译后检查 sys.modules，torch、transformers、sentencepiece 均未加载。

这是当前数据包和测试标签下的后端观察，不是整套桌面应用总内存，不包含浏览器/桌面壳、大型画廊、ComfyUI 或长时间运行；也没有运行旧 Marian 模型进行节省量对比。文件系统缓存、机器负载和标签命中范围会影响耗时。原始记录在 .local/artist-extension-20260911/memory.json 与 stress/memory.json。

## 验证与边界

- V3 后端全套 480 项、前端全套 112 项（23 文件，maxWorkers=2）通过，TypeScript 和生产构建通过。
- 前端覆盖默认关闭不请求、按需推荐、三模式切换保留选择、慢响应失效、输入改变清除名单、标签数量限制、工作台输入和提示词保持，以及设置页迁移后连接操作正常。
- 后端新增验证：即使存在资源路径，V3 工厂也不会探测或构造 Marian；保留词典双向翻译。既有 API 和包边界回归保持有效。
- 真实浏览器使用正式本地标签数据，完成题材贴合→投稿量优先→均衡切换、添加画师、收起再展开；核对要求中同时保留原有 kept_artist 与新选 huhv.，正向提示词未被自动改写。
- 推荐依据编辑和结果名单属于临时面板状态；收起会释放它们，已选画师属于工作台草稿并保留。不会后台持续刷新推荐。
- V2 旧翻译模型实现文件与用户权重仍保留；本轮移除的是 V3 产品运行接线，不宣称整个仓库已不存在模型代码。标签词典翻译继续工作。
- 未调用外部 LLM、未连接云主机、未生成图片。未提交、推送或制作安装包；原开发程序需正常重启加载翻译适配器更新。
