# 身份 tag 补全与个人快捷词

本次补上手动角色、作品、画师输入的功能交互，沿用现有页面结构和视觉。没有调用 LLM 或云端 GPU，没有改写只读参考数据包。

## 使用

- 在「手动角色、作品与画师 tag」对应栏输入中文名、标准英文 tag 或已登记的别名；补全当前行。角色、作品、画师分别检索，避免初音未来被作品 VOCALOID 抢在前面。
- ↑↓ 选择、Enter 确认、Esc 关闭；没有选中候选时 Enter 继续换行。输入法组合期间不选择候选、不发起新检索。250 ms 去抖，并取消和忽略过期请求。
- 可粘贴多行、英文/中文逗号或分号分隔的多个 tag。词库外的自由输入始终保留，可逐个移除；编译沿用既有小写/空格/画师 @ 规则。
- 选择的词与离开输入栏时的非空输入记入最近使用。可收藏、取消收藏；重新打开仍在。角色候选携带数据包中的作品共现建议，必须点击「添加作品」确认，不会自动添加。
- 每类都有「管理别名」：填标准 tag 与自己习惯的中文、日文或其他称呼，保存后可直接搜索。别名明确标注「用户添加」，可删除。已有同名别名指向另一 tag 时拒绝覆盖，需先删除旧映射。

## 搜索证据与限制

正式名称、标准 tag、有效数据包别名的精确命中优先于前缀，关联词次之；不以投稿热度覆盖精确名称。通用标签搜索也同步提升了名称优先级。Unicode 分词不再丢弃平假名、片假名和韩文。

画师存在于数据包独立的 `artists` 表，正式数据包的 `tags` 表没有画师；新接口查询这套真实画师库，不能仅从通用标签 FTS 查画师。

本轮没有自动编造日文别名。当前数据包可以通过 `frieren`、`fuzichoco` 查询；若某个日文名未被上游记录，例如 `フリーレン` 或 `藤ちょこ`，用户可分别登记自己确认的映射后检索。解决假名字符被丢弃，并不等于词库自动获得所有日文名称。

作品关联来源是数据包共现，可能出现联动或多个作品，因此显示为待确认建议。名称补全不是按画风推荐画师；画师投稿量、词库收录、收藏均不证明某个模型学会它。接口返回 `knowledge.status = unknown` 和当前模型 ID，界面明确说明尚未逐项实测。

## 存储与接口

- 个人数据：工作台数据库同目录的 `identity-preferences.db`，与只读参考库、工作台草稿分离；按操作建立短连接并提交事务。
- `GET /api/v3/identities/search`：`kind=character|series|artist`、`q`、可选 `model_profile_id`。
- `GET /api/v3/identities/preferences`：最近使用、收藏、用户别名。
- `POST /api/v3/identities/used`、`PUT /api/v3/identities/favorite`、`PUT/DELETE /api/v3/identities/alias`。
- 所有接口要求本地会话，写入继承相同来源、JSON 大小和内容类型保护。现有词库中的不同分类 tag 不能存入错误分类；未知 tag 可以自由保存。

## 单图人工实测记录

生成结果可展开「记录人工实测」，手动选择角色辨识、构图、结构、风格的「未评／符合预期／不符合预期／不确定」，填写测试 tag 与备注。

一次 `POST /reference-examples/from-run` 同时归档生成图片和 `user_notes`，保留服务端校验过的 run 来源、原始正负提示词、参数、要求以及工作流快照引用。失败保留表单内容；成功可打开参考记录继续管理。没有再次出图、自动打分或新 schema，也不会因为这一条观察把身份补全中的模型知识状态标为已知。

另增前后端各 2 项测试，覆盖原子保存与来源关联、超长备注拒绝、失败重试和只向归档接口提交。
