# 工作台保真优化：实现与验收

2026-09-06。保留中文工作台设计；本轮不改云端模型、LoRA 或工作流配置。

## 已实现

- 部分标签命中时也保留完整画面译文，不再以零散标签替换原意。
- 区分“索引识别证据”和“用户明确追加”。已在译文出现的用户选择项不重复追加；未出现的明确选择仍生效。
- 普通画面只生成一条完整基线，避免 Hybrid 再次拼接整段译文；额外确认的关系仍可生成关系增强版。
- 领域词汇按主体、媒介、效果、服饰、外观、动作、物体、构图、质量分类；较长的已知复合词阻止不相干短标签误确认。
- 本地翻译前保护领域锚点、英文标识、画师句柄与权重；翻译器丢失/重复占位符时改用明确标记的分段兜底，不冒充流畅翻译。
- 中文专名通过本地数据包的唯一主名翻译；少量数据包缺失的拼写收录在 `prompt_identity_aliases.json`，并验证 canonical 确实存在。这不是自动确认角色实体，也不会把共现搜索结果自动注入。
- 中文权重短语（受支持领域词）及英文加权表达保留；括号/引号内的逗号不拆断。
- 逐句记录来源范围、译文和是否需人工核对；界面显示缺失的领域锚点以及原文/译文对照。
- 移除或排除的精确英文词也从最终画面表达过滤，不只是修改标签列表。
- 明确景深/柔焦/色散意图可解除对应默认负向；用户明确负向继续优先。
- Aesthetic 的用户 `score_*` 输入改为可见建议，不再令整个请求 HTTP 500；不默认添加，不静默删除。
- 生成器和校验器共享画面渲染规则，能够检测部分译文被删掉的候选。
- 长中文按受控片段翻译；整段译文超出当前画面计划 2400 字符上限时明确返回 422，不静默截断或内部 500。

## 有意保留的边界

- “完整保留”不等于“机器翻译语义完全正确”。人物朝向、复杂动作关系、照明属性仍有误译可能，界面不会显示已验证全部语义。
- 领域保护只覆盖已知词汇，不是开放世界语义解析器。完整的多主体指代消解、动作所有权、所有修饰语的类型化建模仍需后续扩展。
- 标准年份、质量词仍按明确输入保留，没有实现所有风格元数据与画内文字的语义区分。
- 精确词过滤不能自动理解所有同义表达；用户排除后仍应核对残留关系句。
- 未将更强翻译模型或在线服务默认接入；不下载模型，不上传用户提示词。
- 既有轻量 EXE 打包策略不包含 Torch/Transformers。当前项目启动脚本使用本机 `.venv` 中的 Marian；没有运行依赖的发行环境只能用基础翻译，不能把轻量包启动成功当作 Marian 质量验收。

## 验收方式

代码测试覆盖部分映射不丢场景、候选篡改检测、选词/移除、负向默认调整、score 建议、复合词保护、占位符丢失、长输入、来源范围和权重。前端覆盖画面保真提示、逐句对照以及既有选词/提交功能。

图像测试复用原五案例的模型、无 LoRA、参数和固定负向。第一种子只新增新工作台图，与原始英文/旧标签/旧混合图比较；第二种子对吉他与相机重新生成英文直出、旧混合、新工作台三组。

诊断和原始产物位于项目 `reports/workbench-five-case-audit/`（本地报告目录，不作为产品运行依赖）：

- 原始诊断：`REPORT.md`、`compiled.json`、`renders.json`。
- 新版真实翻译：`retest-compiled.json`。
- 新版第一种子：`optimized-seed1/`、五张 `*-optimized.jpg`。
- 第二种子：`optimized-seed2/`。

图像样本用于发现回归和验证方向，不是统计性非劣效验收。后续仍需未参与词表调试的中文描述、多种子及用户盲评；不得把五条案例硬编码成固定英文答案。
